# 目前介面與操作流程

本文件為目前介面索引。歷史視覺調整與當時的測試範圍見 [UI 整理紀錄](ui-refinement.md)，授權細節見 [權限表](access-matrix.md)。

## 導覽

| 入口 | 顯示名稱 | 範圍 |
| --- | --- | --- |
| `/dns` | 單位 DNS | 目前工作區，成員及管理員皆可清查、送出修改／刪除申請 |
| `/requests/new` | 申請 DNS | 固定目前有效單位 |
| `/requests` | 申請紀錄／申請審核 | 一般成員目前單位；管理員依授權範圍 |
| `/units` | 單位管理 | 單位管理員管理自身單位；系統管理員查看所有單位 |
| `/zones` | DNS 管理 | 合併網域與清查，依 domain 分頁籤 |
| `/admin/application-policy` | 申請規則 | 網域開放設定；全站類型僅系統管理員 |
| `/admin/deletion-protection` | 刪除保護 | 管理員查看狀態；最高管理員設定密碼 |
| `/admin/users` | 帳號管理 | 系統管理員 |
| `/activity` | 操作紀錄 | 系統管理員 |

側欄不分個人／DNS 工作區；僅多個實際單位資格才顯示工作區切換。系統管理員側欄沒有單位 DNS 或申請 DNS，於單位管理查看使用者及 DNS。

## 表單與列表

- 申請表必填姓名、電子郵件、分機與每筆用途；備註選填。用途／備註預設兩行，保留垂直拖曳縮放。
- DNS 管理保留清查列表，沒有多種檢視切換。頁籤涵蓋正解及反解，ee.ncu.edu.tw 與 ce.ncu.edu.tw 優先；搜尋 `@` 找根網域。
- 清查按鈕開啟完整聯絡資料、用途、備註與歷史；系統管理員可在同頁指派正解 DNS 的所屬單位。刪除清查按鈕只對 owner 顯示。
- 清查草稿按紀錄及版本保存在目前頁面，關閉後再開啟可還原；儲存成功清除，重整／離開頁面不保留。
- 單位角色只顯示管理員／成員，兩者可送出申請。管理員可調整角色或「移出單位」；最後一位可登入管理員受保護。
- 系統管理員可建立、指定管理人、改名、確認刪除單位。有 DNS、申請或清查任務關聯的單位不能刪除。
- 「使用者管理」以學號加入；不對使用者使用「白名單」名稱。未註冊者標示等待登入，加入後為成員。

## 驗證限制

元件靜態渲染、草稿處理、API 及隔離資料庫測試不能取代瀏覽器人工操作驗收。Local demo 預設關閉，不為文件或畫面檢查自行啟動；正式畫面、觸控、焦點與不同解析度需另行驗證。
