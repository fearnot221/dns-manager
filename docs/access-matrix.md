# 介面與權限分工

本文件對應目前原始碼與 migration。角色可疊加，但單位角色、網域角色、全域角色各自獨立；導覽及篩選不取代 API／服務層授權。歷次驗證另存於 [歷史紀錄](history/access-changes.md)。

## 角色與功能

| 功能 | 一般使用者 | 網域 ADMIN | 全域 ADMIN／SUPER_ADMIN |
| --- | --- | --- | --- |
| 申請新增／修改／刪除 DNS | 須為有效單位成員或管理員 | 同左 | 仍須實際單位成員資格，側欄不提供申請入口 |
| 清查單位 DNS | 自己有效單位的紀錄 | 同左 | 可使用管理員清查入口 |
| 清查活動（event） | 只讀目前活動名稱與起訖日期 | 同左 | 新增、編輯、刪除及查看所有活動 |
| 單位使用者管理 | 僅自己管理的單位 | 同左 | 所有單位 |
| 建立／改名／刪除單位、指定管理人 | 不可 | 不可 | 可 |
| 查看申請 | 本人及所屬單位 | 另含授權網域 | 全部 |
| 審核單位申請 | 不可 | 不可 | 可，核准前重驗成員及 DNS 狀態 |
| 審核歷史個人申請 | 不可 | 授權網域 | 全部 |
| DNS 管理、清查／歸屬及網域開放申請 | 不可 | 授權網域 | 全部 |
| 全站申請類型規則 | 不可 | 不可；可進頁面管理網域開放設定 | 可 |
| 指派 DNS 所屬單位 | 不可 | 不可 | 可；目前只開放正解網域 |
| 全部 DNS CSV 匯出 | 不可 | 不可 | 可 |
| 刪除保護密碼 | 不可 | 刪除 DNS 時須輸入 | 刪除 DNS 時須輸入；僅最高管理員可設定 |
| 帳號管理、操作紀錄 | 不可 | 不可 | 可；owner 受額外保護 |

網域 VIEWER／EDITOR／ADMIN 保留原有直接／群組授權規則及受保護紀錄限制。上述單位成員不因此取得網域 EDITOR 權限。實際邊界以 [授權程式](../lib/auth/permissions.ts)、[單位規則](../lib/units/policy.ts) 及各服務為準。

## 單位只有兩種角色

| 顯示名稱 | 儲存值 | 權限 |
| --- | --- | --- |
| 成員 | `EDITOR` | 查看單位 DNS／申請、完整清查、送出新增／修改／刪除申請 |
| 管理員 | `ADMIN` | 成員的全部權限，加上使用者加入、角色調整與移除 |

`20260929190000_unit_member_roles` 將原單位 VIEWER 合併為 EDITOR，並從 UnitRole enum 移除 VIEWER；不變更網域 enum。API 不再接受單位 VIEWER。新成員預設 EDITOR，重複加入保留原角色。

「使用者管理」輸入學號，已註冊且啟用的唯一帳號立即加入；未註冊者在登入後自動加入。此資料庫加入名單不同於已停用的全站登入白名單。移出單位或移除加入名單會同步撤銷成員資格；保留最後一位可登入管理員。單位管理員不能自行建立單位或提升全域角色。

系統管理員建立單位時，以學號指定已註冊且啟用的唯一管理人，立即生效；建立者不自動加入。也可為既有單位新增管理人，其他管理人的權限保留。

- 改名：更新單位及目前 DNS 歸屬名稱，歷史申請不改名；名稱重複回傳 409。
- 刪除：移除單位、成員資格及加入名單，保留使用者帳號與稽核。仍有實際 DNS 解析值或待審核申請時回傳 409。直接刪除 DNS 留下的歸屬資料會在確認解析值已不存在後解除關聯；已結案申請及停用功能的舊清查任務解除單位外鍵，保留內容及稽核中的原單位對應。DNS 查詢失敗或來源不符時禁止刪除。
- 單位審核已停用；舊制未啟用單位仍不可申請，不因升級自動啟用。新建立單位預設 APPROVED（介面為「啟用」）。

## 申請、清查與復原

申請固定 `UNIT_ONLY`，不接受個人模式。新增申請必填姓名、電子郵件、分機及每筆用途；單位名稱由伺服器取自 unitId，備註選填。未設定開放的網域預設暫停申請；各網域開關與全站類型規則都在後端驗證。

核准單位申請需檢查提交者仍啟用、仍為成員、單位有效、連線來源及 DNS 快照一致。成員被移除後，其待審申請不能照舊核准。申請送出不改 DNS，管理員核准才寫入。

完整清查表單可更新聯絡資料、用途及新增備註歷史；單位欄位由伺服器依歸屬決定。清查不修改 DNS。時間與經手人不可由客戶端指定；紀錄版本／快照衝突回傳 409。

清查草稿存在目前頁面記憶體，依紀錄與版本隔離。關閉後再開啟可繼續填；儲存成功清除，離開或重整頁面不保留。舊版本草稿不套用到新版本資料。沒有持久瀏覽器草稿或自動提交。

清查活動由全域管理員於 `/admin/inspection-events` 管理；一般使用者在單位 DNS 只看到目前活動名稱與起訖日期。日期以 Asia/Taipei 計算，含起訖日，同時只能有一個活動，重疊期間回傳 409。清查隨時可做，不受活動期限限制。新增紀錄由伺服器依清查時間保存活動 ID／名稱快照，或標記「非活動期間清查」；改名、改期或刪除活動不改寫歷次標記。升級前的紀錄顯示「舊紀錄（未標記活動）」，不推測歸屬。詳見 [清查活動](inspection-events.md)。

DNS 復原僅還原 RRset，保留原 TTL、值及停用旗標等快照內容；不回復單位歸屬、申請審核狀態或清查歷史。缺少完整快照／來源、連線變更、DNS 已有後續修改時拒絕覆蓋。舊事件可能只能查看不能復原；PowerDNS 外部變更不會自動匯入。

## 最高權限與帳號管理

owner 為本次 Logto 登入驗證的一致 NCU identity `details.identifier=115502532`，且解析為 SUPER_ADMIN；email、姓名、sub、備註或資料庫舊角色不能替代此證明。

全域管理員可修改其他非 owner 帳號的 USER／ADMIN 身份及狀態，包含其他 ADMIN；owner 角色與狀態不可改，備註可編輯。移除帳號、委派網域權限、刪除清查歷史限 owner。介面不額外標示最高管理員專屬提示，刪除清查按鈕只對符合權限者顯示。

## 已撤除或相容入口

- 自行建立單位、加入碼及單位審核：不再受理。
- 使用者訊息、清查通知／回覆管理：舊頁面 404、API 410；保留舊資料但不提供操作。
- 全站登入白名單：不限制現在的登入；與單位使用者管理無關。
- PowerDNS 網頁設定：頁面 404、舊設定 API 410；僅 env 生效。
- 網站新增 Zone：停用；直接 DNS 管理仍須既有授權。
- `/inventory`、`/zones/[zone]`：相容轉址到整合的 `/zones`。

## 驗證範圍

以 [README 的驗證指令](../README.md#開發與驗證) 執行 build、lint、測試。資料庫與 migration 測試只能用隔離資料庫，mock PowerDNS 不代表正式 DNS、Logto 或 Caddy 已驗證。純文件更新檢查差異、路徑與規則一致性，不重跑應用 build；local demo 保持關閉。
