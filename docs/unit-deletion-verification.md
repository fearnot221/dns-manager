# 單位刪除修正與驗證（2026-09-29）

程式碼狀態：基底 `250013e` 上本次未提交工作樹；本次未推送或部署。

## 問題與修正

舊實作計算全部 DNS 歸屬、申請及清查任務關聯，因此即使 DNS 已刪除，已結案申請與殘留歸屬仍會永久阻擋單位刪除。

修正後：

- 保留原有系統管理員權限檢查、帳號及單位鎖定。
- 待審核申請仍阻擋刪除，錯誤訊息列出件數。
- 對剩餘歸屬資料，在 DNS 網域鎖內查詢實際解析值；仍存在（包含停用值）即禁止刪除。已刪除 Zone 的明確 404 視為不存在；其餘查詢錯誤及不同連線來源均拒絕刪除。
- 確認沒有 DNS 後，解除失效歸屬、已結案申請及舊清查通知任務的單位外鍵，再刪除單位。保留 DNS 中繼資料、清查紀錄、申請內容及任務快照；申請欠缺原單位名稱時補入名稱。
- 清查通知功能已停用，因此包含舊 PENDING 任務在內皆按歷史資料保留，不重新分派或刪除。
- 稽核保留單位 ID／名稱及解除關聯的紀錄、申請與任務 ID。成員與加入名單隨單位刪除，使用者帳號保留。整個資料庫變更在同一交易內完成，不寫入 PowerDNS。

## Migration

`20260929233000_archive_deleted_unit_tasks` 新增 `InspectionTask.archivedUnitId`／`archivedUnitName`，保存已刪除單位的歷史收件對象。原收件人限制仍要求「使用者、現存單位、歷史單位」恰有一個，歷史 ID／名稱須成對存在。既有資料不回填、不移除，舊外鍵保護仍保留。部署須先套用 migration 再啟動新版 web；既有 Compose 流程會依此順序執行。
